OxiCloud loader variants

Candidates to replace the plain spinner shown while the app boots. Each is pure CSS stroke-dash animation on the existing logo path — no JavaScript, no new artwork — and each works inside an <img src>, which is what lets one file serve the boot splash, the in-app loading screen and the no-JavaScript fallback alike.

Pick the one you prefer and reply with its letter in the thread where you got this link. In each tile the left shape is today's 38px size and the right is 64px — a variant that only works at 64px means the loader has to grow, so judge both.

0 · Today's ring

What ships now. Reference only — no logo in it at all.

A · Snake on the circle

Logo filled and still, one dash orbiting an enclosing circle. Uniform curvature, so the dash reads at a constant speed.

B · Snake on the cloud outline

The dash traces the cloud itself, unfilled. Most distinctive; watch the flat bottom edge and the tight corners, where a dash sized for the straight run can look long.

B↺ · Same, counter-clockwise

B with the dash running the other way, for comparison. Clockwise is what the circle variants do, so B above now matches them.

C · Ghost logo + contour snake

Same path as B, but the glyph stays faintly filled so the mark is readable even mid-animation. Reads as "the logo is drawing itself".

D · Two dashes on the circle

Variant A with a second dash starting half a lap behind and running at half the speed, so the two lap each other and the figure keeps changing.

E · Brand logo + theme-aware snake

Solid #ff5e3a glyph, clockwise dash on its contour. The dash colour flips with the theme — white on dark, #0f172a ink on light, so both halves of the stroke contrast in either case.

Colours here are the real literals (#ff5e3a accent, #e2e8f0/#334155 track, #f5f7fa/#0f172a background) because an SVG inside an <img> cannot read CSS custom properties — dark mode would come from a @media (prefers-color-scheme) block inside the file. With prefers-reduced-motion: reduce every variant above holds still.
